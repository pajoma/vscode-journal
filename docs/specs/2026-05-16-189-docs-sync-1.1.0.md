## In scope

### A. CHANGELOG.md — missing closed-issue entries

- **#170** (Wrong day set when entering an entry): Add a "Fixed" entry. The bug: entering text starting with a two-letter weekday abbreviation (e.g., "Do" for Donnerstag in German) triggered date parsing before the full word was typed, setting the wrong date on the entry. Fixed by improving the prefix-collision detection in the parser.
- **#145** (Option to disable opening journal when using quick memo): Add an "Added" entry. Implemented as `journal.memo` command — an alias for the smart input (`journal.day`) registered separately so users can bind it to a key or invoke it from the command palette without the full journal view opening.

Verify no other closed 1.1.0 milestone issues are missing; if found, add them.

### B. README.md — prev/next navigation feature mention

Add one bullet to the feature list (after the existing smart input bullet, before the "markdown notes" reference) describing `journal.openPrevious` / `journal.openNext` and referencing `docs/commands.md` for keybindings.

### C. .github/CONTRIBUTING.md — engine version

### H. package.json — journal.locale deprecationMessage

Add `"deprecationMessage": "This setting is no longer used. The extension falls back to your editor's Display Language setting (vscode.env.language)."` to the `journal.locale` property in `contributes.configuration.properties`. Without this, the VS Code settings UI does not render the key as deprecated despite the docs labeling it so.

### I. src/actions/navigation.ts — JSDoc on public API

Add JSDoc to:
- `Direction` type: `'previous' | 'next'` — direction of navigation.
- `Mode` type: `'existing' | 'calendar'` — whether to skip gaps or step one calendar day.
- `Anchor` interface: the resolved date + scope from which navigation begins.
- `resolveAnchor(ctrl, editor)`: explain the fallback chain (editor's file → `getDateFromURIAndConfig` → today if parsing fails or editor is undefined) and scope resolution.
- `findAdjacentEntry(ctrl, anchor, direction, mode)`: document both modes — `calendar` returns `addDays(±1)` immediately; `existing` delegates to `walkForAdjacent` which scans the FS.

No behavior changes — JSDoc only.
