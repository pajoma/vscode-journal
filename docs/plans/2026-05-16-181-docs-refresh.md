# Plan: Docs refresh — keybindings + configuration (#181)

**Reference spec:** [docs/specs/2026-05-16-181-docs-refresh.md](../specs/2026-05-16-181-docs-refresh.md)

## Approach

Single docs-only PR (`docs/181-docs-refresh`) against `develop`. No runtime code touched. Work in five logical chunks (A–E) that can be committed independently for easier review. Use `package.json` as the authoritative source throughout — run completeness checks at the end to validate.

Main trade-off: documenting the 11 `journal.tpl-*` keys (which are NOT marked deprecated in the manifest) thoroughly vs. briefly. Brief wins: one "Legacy template keys" table with migration pointer keeps settings.md readable without suggesting these keys are a preferred path.

## Steps

### 1. Branch

Create `docs/181-docs-refresh` from `develop`. Docs-only — no esbuild, no `tsc`, no tests needed.

*Why: isolate the docs change from any in-flight feature work.*

### 2. Fix `docs/commands.md` (chunk A)

Changes:
- Replace all `journal:day` / `journal:today` etc. occurrences → `journal.day` / `journal.today` (dot, not colon). The existing file already uses `journal:` which is wrong.
- Restructure as a table or clear list with columns: Command ID | Default keybinding (Win/Linux) | Mac equivalent | `when` clause | Description.
- `journal.day`: `Ctrl+Shift+J` / `Cmd+Shift+J` | no `when` clause.
- `journal.printDuration`: `Ctrl+J D` / `Cmd+J D` | `editorTextFocus && editorHasMultipleSelections`.
- `journal.printSum`: `Ctrl+J S` / `Cmd+J S` | `editorTextFocus && editorHasMultipleSelections`.
- `journal.openPrevious`: `Ctrl+J ,` / `Cmd+J ,` | `editorTextFocus`.
- `journal.openNext`: `Ctrl+J .` / `Cmd+J .` | `editorTextFocus`.
- Add "How to rebind" section: point to `File → Preferences → Keyboard Shortcuts`, show minimal `keybindings.json` snippet for a journal command.
- Add "Localization" paragraph: command titles and prompts use `vscode.l10n`; list eleven locales (en, de, fr, es, it, pt, nl, ru, zh, ja, ar); falls back to English for any locale not listed.

*Why: commands.md is the single source reviewers and users consult for keybindings; wrong command-id syntax and missing entries break that promise.*

### 3. Fix `docs/print.md` (chunk A, same commit)

- Replace `Ctrl+J Ctrl+D` → `Ctrl+J D`.
- Replace `Ctrl+J Ctrl+S` → `Ctrl+J S`.

*Why: print.md currently documents non-existent two-key chords; this silently breaks for users who follow the doc.*

### 4. Fix `docs/settings.md` (chunk B)

Changes in order of appearance in the file:

**a. Variables table (top of file)**
- Add `${week}` row: ISO week number (1–53).

**b. Base directory section**
- Expand `journal.base`: note that the default is `${homeDir}/Journal` where `${homeDir}` resolves via Node's `os.homedir()` (covers `$HOME` on Linux/Mac and `%USERPROFILE%` on Windows).
- Add untrusted-workspace note: in untrusted workspaces, `journal.base` workspace-level overrides are ignored; the user-level value is used instead (VS Code `restrictedConfigurations`).

**c. Patterns section**
- Add `weeklyNotes` block to the pattern table: `path: ${base}/${year}/w${week}`, `file: ${input}.${ext}`. Note it is used when `journal.entryGranularity = "weekly"` and a note (not entry) is created.

**d. Templates section**
- Update the default `journal.templates` example from 6 entries to 8: add `weekly` (`# Week ${week}\n\n## Tasks\n\n## Notes\n\n## Daily Entries\n\n`) and `dailyLink` (`- [${weekday}, ${d:MMMM DD}](${link})` with `after: "## Daily Entries"`).

**e. New "Legacy template keys" section** (after the templates section)
- Add a table listing all 11 `journal.tpl-*` keys (`journal.tpl-entry`, `journal.tpl-time`, `journal.tpl-note`, `journal.tpl-memo`, `journal.tpl-memo-after`, `journal.tpl-task`, `journal.tpl-task-after`, `journal.tpl-todo`, `journal.tpl-todo-after`, `journal.tpl-files`, `journal.tpl-files-after`) with their purpose.
- One-paragraph note: these keys predate the unified `journal.templates` array; both mechanisms are supported but `journal.templates` is preferred for new configuration. Migration: move the value from e.g. `journal.tpl-memo` into the `template` field of the `"memo"` entry in `journal.templates`.

**f. Syntax highlighting section** (after "Other options")
- Expand the existing one-liner into a proper section: explain that `journal.syntax-highlighting` enables extension-specific syntax highlighting, defaults to `false`, writes color tokens into user settings on first activation, and that deleting the injected color customizations causes them to be re-inserted on the next start.

**g. Virtual-workspace note** (at the bottom of settings.md or top, near the base directory)
- Add one paragraph: vscode-journal declares `virtualWorkspaces: limited` — in a virtual workspace, write operations to local paths are unavailable; read-only browsing of existing entries may still work.

*Why: spec acceptance criterion requires zero setting keys missing in either direction.*

### 5. Create `docs/weekly-entries.md` (chunk C)

Structure:
1. **Overview** — what weekly entries are (ISO-week files) and when they are useful.
2. **Opening a weekly entry** — type `w20` (or `w<NN>`) in the smart input; or set `journal.entryGranularity = "weekly"` so bare input goes to the current week.
3. **Entry granularity** — brief recap; link to `settings.md#entry-granularity` for full reference.
4. **Daily Entries auto-sync** — how the `## Daily Entries` block is maintained automatically; the anchor requirement (`journal.weeklySync.anchor`); graceful degradation when anchor is absent.
5. **Customization** — `journal.weeklySync` fields (enabled, anchor, template variables, sortOrder); link to `settings.md#weekly-sync`.
6. **Disabling sync** — set `journal.weeklySync.enabled = false`.
7. **Pattern** — `journal.patterns.weeklyNotes`; link to `settings.md#path-patterns`.
8. Footer: "→ [Commands](./commands.md) · [Settings](./settings.md)"

*Why: the weekly workflow was added in #168 and #185 but has no dedicated narrative doc; users land here from the smart input reference.*

### 6. Footer cross-references (chunk D)

For each of `docs/memo.md`, `docs/tasks.md`, `docs/notes.md`, `docs/print.md`, `docs/codeactions.md`, `docs/scopes.md`, `docs/smartInput.md`:
- Append a footer line: `→ [Commands](./commands.md) · [Settings](./settings.md)`

Also add to `docs/settings.md` "Weekly Sync" section: cross-link `→ See [Weekly Entries](./weekly-entries.md) for the full workflow.`

README.md already links to both files (lines 36, 52). Confirm the links are present and accurate; no structural change needed unless the links are broken.

*Why: reviewers and new users currently cannot navigate between docs; each file is a dead end.*

### 7. Delete `docs/into.gif` (chunk E)

- Verify `into.gif` is referenced nowhere (`grep -r "into\.gif" docs/ README.md`).
- Delete the file.
- Keep `intro.gif` (also unreferenced but the correct spelling — do not delete both in case it gets linked in the future).

*Why: the file is an orphaned typo artifact; keeping it creates confusion about whether it differs from `intro.gif`.*

### 8. Completeness checks before PR

Run these before opening the PR:

```bash
# Keybinding check: every command in package.json keybindings appears in commands.md
node -e "const p=require('./package.json'); p.contributes.keybindings.forEach(b => console.log(b.command))" | while read cmd; do grep -q "$cmd" docs/commands.md || echo "MISSING: $cmd"; done

# Setting key check: every key in package.json appears in settings.md
node -e "const p=require('./package.json'); Object.keys(p.contributes.configuration.properties).forEach(k => console.log(k))" | while read key; do grep -q "$key" docs/settings.md || echo "MISSING: $key"; done
```

Fix any gaps found before opening PR.

## Risk

- **tpl-* keys underdocumented:** If the migration note is unclear, users may not know to move their config. Mitigation: include a concrete before/after example.
- **into.gif external links:** A third-party tutorial or blog post might link the file. Mitigation: the file is not referenced in the repo itself; deleting it is low-risk. GitHub blob URL would 404 after deletion regardless of whether it's in git history.

## Rollback

Revert the docs PR. No runtime impact — docs changes cannot break the extension.
