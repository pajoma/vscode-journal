# VS Code 1.120 Upgrade — Design

> Created: 2026-05-13
> Status: Design approved, ready for implementation plan
> Scope: Engine + dependency bump + manifest modernization + l10n migration
> Out of scope: PLAN.md Phase 2+ (DI, async refactor, moment removal, performance, features)

---

## 1. Goal

Lift `vscode-journal` from the VS Code 1.94 baseline (October 2024) to 1.120 (May 2026), modernize the extension manifest to use APIs and patterns that have stabilized in the intervening ~14 releases, and remove dead dependencies. CI green at every step.

### In scope

- `engines.vscode` and `@types/vscode` pinned to `^1.120.0`
- Toolchain bumps: TypeScript, esbuild, ESLint + `@typescript-eslint/*`, `@vscode/test-cli`, `@vscode/test-electron`, Mocha + `@types/mocha`
- Drop redundant `activationEvents` block (implicit activation since 1.74)
- Drop unused `@vscode/extension-telemetry` dependency
- Declare `capabilities.virtualWorkspaces` and `capabilities.untrustedWorkspaces` in `package.json`
- Migrate the custom `messages.json` + `translations.ts` translation system to `vscode.l10n` (finalized in 1.73)
- Add `@vscode/l10n-dev` as a development dependency for bundle generation

### Out of scope

Anything in `PLAN.md` Phase 2 and later: dependency injection refactor, `import * as J` namespace cleanup, `new Promise()` → `async/await` rewrite, removing `moment` (Phase 3), performance work (Phase 4), code-quality cleanup (Phase 5), feature work (Phase 6), expanded test coverage (Phase 7), release packaging (Phase 8). Each of those is independently scheduled and not bundled into this upgrade.

## 2. Current state (audited 2026-05-13)

- `engines.vscode: ^1.94.0`, `@types/vscode: ^1.94.0` — 26 releases behind stable.
- `activationEvents` lists 11 `onCommand:journal.*` entries; all 11 commands also appear in `contributes.commands`. Implicit activation has covered this since 1.74, so the entire block is redundant.
- `@vscode/extension-telemetry@^0.5.0` declared as a runtime dependency. `grep -rn "extension-telemetry\|TelemetryReporter\|telemetryReporter" src/` returns zero matches — the dependency is dead code.
- Translation system: `src/ext/messages.json` (299 lines, `en` and `de` locales, four categories: `descriptions`, `labels`, `picks`, `details`) and `src/ext/translations.ts` (126 lines, custom lookup keyed on `vscode.env.language.substring(0, 2)`). Seven `getInput*Translation` exports in `src/ext/index.ts` consume it. Command titles, configuration descriptions, etc. in `package.json` are hard-coded English only.
- No `capabilities` block declared. `extensionKind: ["workspace"]` is set (correct).
- Production code no longer uses raw Node `fs` (PLAN.md Phase 1.3 migrated everything to `vscode.workspace.fs`). Tests still use `fs` — acceptable, they run in Node.
- `moment@^2.29.4` used in `src/util/dates.ts`, `src/util/paths.ts`, `src/util/logger.ts`, and `src/ext/dialogues.ts`. Untouched in this upgrade — PLAN.md Phase 3 owns the migration.

## 3. Layered changes

Three layers, three commits, each independently revertable.

### Layer 1: Mechanical dependency bump

Update `package.json` to the table below. Exact patch versions resolved at execution time via `npm outdated`; the listed targets are the floor.

| Package | Current | Target | Notes |
|---|---|---|---|
| `engines.vscode` | `^1.94.0` | `^1.120.0` | Latest stable as of 2026-05-13 |
| `@types/vscode` | `^1.94.0` | `^1.120.0` | Must match `engines.vscode` |
| `@types/node` | `20.x` | `20.x` | Node 20 LTS, unchanged |
| `typescript` | `^5.6.3` | `^5.7.x` (or current stable 5.x) | |
| `esbuild` | `^0.24.0` | `^0.25.x` | Output is CJS, format stable across these |
| `eslint` | `^9.13.0` | `^9.x` latest | Flat config preserved |
| `@typescript-eslint/eslint-plugin` | `^8.10.0` | `^8.x` latest | Pair with parser |
| `@typescript-eslint/parser` | `^8.7.0` | `^8.x` latest | |
| `@vscode/test-cli` | `^0.0.10` | latest `0.0.x` | |
| `@vscode/test-electron` | `^2.4.1` | latest `2.x` | |
| `mocha` | `^10.8.2` | `^10.x` latest, or `^11.x` if test fixture passes | TDD UI must keep working |
| `@types/mocha` | `^10.0.9` | match `mocha` major | |

**Action sequence:**
1. `npm outdated` to read current upstream versions.
2. Edit `package.json` per the table.
3. `npm install`.
4. `npm run check`. If failures, fix in-place: lint rule churn → `eslint --fix`; type errors from richer `@types/vscode` → narrow types or add explicit casts.
5. Update CI workflow (`.github/workflows/ci.yml`) to also run on `node-version: "22"` alongside `"20"`. Both matrix legs must pass.

**Verification gate:** `npm run check` clean, both Node 20 and Node 22 CI legs green, no new ESLint warnings.

### Layer 2: Manifest cleanup

Three edits in `package.json`, no source changes.

**Drop `activationEvents`.** Remove the entire `activationEvents` array. All 11 declared commands are in `contributes.commands` and activate implicitly. The `journal.test` command, flagged for removal in PLAN.md Phase 2.4, is also dropped from `contributes.commands` (and its source registration in `src/ext/startup.ts`, if present) — if the user wants to retain it as a dev-only command, re-add it as a sole `onCommand:journal.test` entry rather than restoring the whole block.

**Drop `@vscode/extension-telemetry` dependency.** Remove the entry from `dependencies`. Run `npm install` to refresh `package-lock.json`. Re-run `grep -rn "extension-telemetry\|TelemetryReporter" .` outside `node_modules`/`dist`/`out` to confirm no residual import resurfaces from a stale build.

**Add `capabilities` block.** Insert at the top level of `package.json`:

```json
"capabilities": {
  "virtualWorkspaces": {
    "supported": "limited",
    "description": "vscode-journal stores entries on a real filesystem path resolved from `journal.base`; virtual workspaces are not supported."
  },
  "untrustedWorkspaces": {
    "supported": false,
    "description": "vscode-journal writes files to the directory configured in `journal.base`, which can be set in workspace settings. Trust is required."
  }
}
```

Rationale:
- `virtualWorkspaces`: `src/ext/conf.ts` uses `os.homedir()` to resolve the default base directory. Node's home path is meaningless on a virtual filesystem provider, and the file walker (`provider/features/scan-entries.ts`) uses `vscode.workspace.fs` against that resolved path. Marking `limited` keeps the extension installable in virtual workspaces while warning users.
- `untrustedWorkspaces`: a malicious workspace can set `journal.base` in its `.vscode/settings.json` to redirect file writes (memo/task/note/entry inject) to an arbitrary path on the host. Requiring trust is the appropriate boundary.

**Verification gate:**
- Launch via F5 with **no** workspace open. Run `journal.today`. Confirm extension activates on first command (Output channel "Journal" appears post-invocation, not at startup). Validates implicit activation.
- Open `test/ws_manual/` as an **untrusted** workspace (via "Don't Trust" on the prompt). Open the command palette: journal commands appear but executing one shows the standard trust prompt before any file write. Validates `untrustedWorkspaces: false`.
- Verify `dist/extension.js` size shrinks after telemetry dep removal (`ls -l dist/extension.js` before and after).

### Layer 3: `vscode.l10n` migration

Replace the custom translation system with the stable `vscode.l10n` API.

**Files added:**

- `package.nls.json` — defaults (English) for `package.json` static contributions. Example keys: `command.journal.today.title`, `configuration.journal.base.description`, etc. Referenced from `package.json` as `%command.journal.today.title%`.
- `package.nls.de.json` — German overrides. Sourced from existing `messages.json` `de` strings where they correspond to a `package.json` field; new entries translated for any field that was English-only.
- `l10n/bundle.l10n.json` — extracted runtime English strings from all `vscode.l10n.t(...)` call sites.
- `l10n/bundle.l10n.de.json` — German runtime translations. Sourced from `messages.json` `de` entries.

**Files removed:**

- `src/ext/messages.json`
- `src/ext/translations.ts`
- All seven `getInput*Translation` and `getPickDetailsTranslation` exports from `src/ext/index.ts`

**`package.json` edits:**

- Add `"l10n": "./l10n"` at the manifest top level. (Tells VS Code where the runtime bundle lives.)
- Add `@vscode/l10n-dev` to `devDependencies` at the current latest.
- Add an npm script: `"l10n:export": "@vscode/l10n-dev export -o ./l10n ./src"`. Used to refresh the bundle when source strings change.
- Replace literal command titles and configuration descriptions in `contributes.commands` and `contributes.configuration.properties` with `%key%` placeholders that resolve against `package.nls*.json`.

**Source edits:**

- Every call site of `J.Extension.getInputLabelTranslation("today")` etc. rewrites to a direct `vscode.l10n.t("Today")` (or `vscode.l10n.t({ message: "Add task to entry {day}", args: { day: ... }, comment: ["{day}: ISO date"] })` for parameterized strings).
- Remove the `messages` import from `src/ext/translations.ts` along with the file itself.
- Strings that were keyed by integer (`labels.1` etc.) become inline English literals at the call site — the literal *is* the translation key in the `vscode.l10n` model.

**Verification gate:**
- `npm run check` clean.
- Launch Extension Development Host with `--locale=de` argument. Confirm:
  - Command palette entries (`Journal: Heute öffnen` etc.) render in German.
  - QuickPick `description` and `detail` fields render in German when invoking `journal.day` / `journal.note`.
  - Settings UI shows the German description for `journal.base`.
- Launch with no `--locale` (defaults to system locale, likely `en` on CI). Confirm fallback strings render correctly.
- Run `npm run l10n:export` and diff `l10n/bundle.l10n.json`: should match the committed file (no missing strings).

## 4. Sequencing and rollback

**Branch.** Single feature branch `feature/vscode-1.120-upgrade` cut from `develop`. Three commits, one per layer, in order. Push after Layer 1 is locally green; open a PR. Layers 2 and 3 push onto the same PR or split into follow-up PRs at execution time.

**Gate per layer.** Each layer must satisfy its own verification gate (Section 3) before the next layer commits. CI must be green on the layer's commit before moving on. Manual smoke check is part of the gate, not a follow-up.

**Rollback.** Each layer is one commit. If a layer breaks something not fixable within roughly two hours of investigation, `git revert <layer-commit>` removes it cleanly without touching earlier layers. Layer 1 cannot revert because subsequent layers depend on its types — but if a Layer 1 dep bump proves toxic, narrow the bump to the offending package and continue.

## 5. Risks

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| ESLint flat-config rule churn breaks lint | low | low | `eslint --fix` once; review remaining diffs |
| `@vscode/test-cli` config breaks | low | medium | Read changelog, update `.vscode-test.mjs` |
| Mocha 10 → 11 breaks TDD UI | medium | low | Stay on Mocha 10 if 11 needs migration; not blocking |
| Richer `@types/vscode` surfaces deprecation warnings on existing calls | high | benign | Address per case during Layer 1; do not silence en masse |
| `capabilities.untrustedWorkspaces: false` surprises existing users in untrusted folders | medium | low | Document in `CHANGELOG.md`; users dismiss trust prompt once |
| `vscode.l10n` resolution differs from old `vscode.env.language.substring(0,2)` heuristic for some locales | low | low | `vscode.l10n.t()` falls back to default literal; no broken-UI failure mode |
| Bundle bundle generation drift between dev runs | low | low | CI step `npm run l10n:export && git diff --exit-code l10n/` (optional, can defer) |
| esbuild 0.24 → 0.25 changes output for `external: ['vscode']` projects | low | low | CJS output, `extension.js` shape unchanged; verify file loads in EDH |

## 6. Testing strategy

**Automated.** Existing test suite in `src/test/suite/` runs unchanged across all three layers. Layer 1 may surface compile or runtime failures from stricter `@types/vscode`; fix the production code (or the test) rather than weakening types. No new automated tests are required for the upgrade scope itself — the existing parser/reader/writer regression coverage already protects domain behavior.

**Manual smoke (documented per layer in Section 3).** Three checks, each tied to a specific layer:

- **Layer 1:** `npm run check` plus the test suite running in Extension Host (already covered by CI).
- **Layer 2:** cold-start activation check (Output channel doesn't appear until first command invocation) + untrusted workspace check (trust prompt before any file write).
- **Layer 3:** German locale check via `--locale=de` launch arg.

**CI changes.** Add Node 22 to the existing matrix (currently Node 20 only). Keep Node 20 leg until LTS support drops. Keep `xvfb-run` wrapper for the test step.
